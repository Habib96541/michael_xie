Goals and why

Changes

  0, 1.8, -1.8, 2.4, -2.2, 1.6, -2.6, 2.0, -1.4, 2.6, -2.0, 1.4

Manual check for the user
1. Exit Play mode. If Unity has no unsaved scene edits, reload the saved FlapDash scene when prompted about the external change.
2. If you have unsaved scene edits, preserve them first and enter the 12 values above into Pipe Course / Gap Centers. Saving a stale seven-entry scene would overwrite this file change. Do not regenerate the scene.
3. Confirm the array has 12 entries. Let Unity compile, then check the Console for errors, including the earlier optional-title error.
4. Start a round and test climbing and falling through successive openings. Review the largest 4.6-unit changes rather than only the centered first pipe.
5. Test the last-to-first transition when the sequence repeats. Restart and confirm the first opening returns to center zero.
6. Confirm your revised menu is intact and report whether the steep changes feel fair. WebGL remains the old Sprint 03 build.

Explanation and concepts learned
- gapCenters is an ordered collection of vertical opening positions. Positive values raise an opening; negative values lower it.
- A saved Unity scene stores serialized Inspector values. Changing a C# field initializer does not replace those saved values, so the actual scene array must also change.
- The generator source needs matching values for future authoring consistency, but running it now would replace the custom scene layout.
- Larger center changes demand more steering. A smaller opening would instead reduce clearance and precision tolerance.

Senior note
- Bounds alone do not prove a course is fair. Check whether the player can read and reach steep transitions with the current velocity and available time before accepting the difficulty.

RULES, STATES, AND CONTROLS

Home -> Preview -> CameraTransition -> Playing -> Jumping -> Won/Falling/TimedOut -> Results.
Pause and dialogs gate input separately while preserving the underlying run state.

Each row has one safe side chosen once when the run is created. The entire safe path is shown during preview, then all safety markers are hidden. Both panels use identical visuals and support colliders until a fragile landing resolves. Only the immediately next row can be selected. The final safe panel is followed by an automatic jump to the finish platform.

A / D selects the next left / right panel. Mouse clicks and touches work on valid next-row panels. Large left/right buttons provide easier targets on touch devices. Holding a key does not repeat a choice. Extra inputs during a jump are ignored, UI clicks do not select world panels, and preview, transitions, pause, results, and dialogs block gameplay choices. Escape opens pause.

Jumps have a controlled visible arc. A 3D spherecast must find the expected support collider before landing resolves. Fragile support is disabled after contact, then the contestant falls with 3D gravity. Decorative shards have no gameplay authority. Physics uses no 2D components.

The timer advances during jumps. It is evaluated before landing in the controller update. At the exact timeout/landing boundary, timeout takes priority. A landing completed while positive time remains may resolve; terminal states cannot be overwritten. A run identifier and terminal guard prevent duplicate winning payouts.

DIFFICULTY AND REWARD CONFIGURATION

             Rows   Preview   Timer   Completion bonus   Full winning payout
  Easy        6       5s       30s           50                 260
  Normal     10       4s       45s          100                 650
  Hard       14       3s       60s          200                1250

Successful step n adds 10 * n provisional coins. A win banks all provisional step coins plus the completion bonus once. Death, timeout, Restart, Home, closing the page, or reload pays zero for that round. Previously banked winnings remain saved. Retry is free. Tunable values live in Sprint1.asset; ordinary builds do not reset them. Deterministic default tests use an independent default configuration, and additional checks validate the currently serialized configuration.

SAVING

PlayerPrefs key: ShatterLeap.Save.v1, containing versioned JSON.
Saved fields: banked integer coins, difficulty index, music/sound volumes, vibration, reduced camera effects, last paid run identifier.
Defaults and validation recover from missing/malformed saves, unsupported versions, negative coins, invalid difficulty, and invalid volume values. Volumes are clamped. Preferences are saved on change. A win writes the wallet and payout identifier together, followed by PlayerPrefs.Save. Active runs and provisional earnings are never serialized.

The Web template opts into automatic persistent-data synchronization. Browser storage is local to the origin/profile; clearing it removes the wallet. There is no cloud/account synchronization. Save/load and malformed-data recovery were exercised by deterministic checks; actual browser winning-wallet persistence was verified across reloads.

WEB BUILD AND HOSTING

Delivered folder: Builds/Web
Entry point: Builds/Web/index.html
Files: index.html, logo.png, Build/Web.loader.js, Build/Web.framework.js, Build/Web.data, Build/Web.wasm.
Complete size: 71,890,356 bytes (about 71.9 MB decimal / 68.6 MiB), uncompressed.
BuildManifest.txt records SHA-256 hashes and lengths of the delivered files.

Web settings: single-threaded WebAssembly, compression disabled, 128 MiB initial memory, 1024 MiB maximum growable memory, DPR capped at 1.5, browser caching enabled, custom responsive template. CSS safe-area insets protect the canvas on supporting browsers. Fullscreen is exposed where the browser supports it and gracefully hidden on failure/unsupported browsers.

A separate Web forward renderer uses SDR, 2x MSAA, no renderer features, and no realtime shadow maps. This resolved WebGL sampler failures observed in the first compiled build. Existing PC/Mobile render-pipeline assets were preserved. Build tooling temporarily overrides the quality pipelines for the compiled player and restores the complete native quality settings afterward.

Local launch, from the project directory:
  python Tools/serve.py
Then open:
  http://127.0.0.1:8080
For a phone on the same LAN:
  python Tools/serve.py --bind 0.0.0.0
Then browse to the computer's LAN address on port 8080. Network/firewall access must permit the connection. No physical phone LAN test was executed.

Build an existing game:
  powershell -File Tools/Build-Web.ps1
Or use Unity menu ShatterLeap > Build Existing Web Game.
Setup missing assets only:
  powershell -File Tools/Build-Web.ps1 -Setup
The setup command preserves existing scene/configuration/prefabs. Normal builds do not regenerate character art, scene contents, or user configuration. Tools/editor.py queues inspection, refresh, setup, validation-related, test, and build commands into the open editor. Assets > Refresh may be needed if the editor has not imported new scripts.

Static hosting: upload every file under Builds/Web while preserving relative paths. Serve .wasm with application/wasm, .js with JavaScript MIME, .data with application/octet-stream. These files have no gzip/Brotli Content-Encoding; do not label raw bytes as compressed. This build needs no COOP/COEP headers because it uses no WebAssembly threads. HTTPS is recommended for public hosting. HostingChecks.txt records successful HTTP 200 HEAD responses and actual content types. Public deployment is outside this sprint's delivery.

KNOWN LIMITATIONS

- Physical iPhone/Android and macOS browser certification remains to be performed. Touch emulation does not establish Safari compatibility or physical-device performance.
- The uncompressed 71.9 MB distribution is straightforward to host but a substantial initial download. Public-host compression/network optimization can be evaluated after selecting a host.
- Chrome/Edge logged WebGL capability/resize warnings (INVALID_ENUM getInternalformatParameter; drawBuffers BACK or NONE). No JavaScript, Unity runtime exception, or resource-load errors were observed in the final automated browser checks; inspected rendering remained correct. These warnings are retained in WebChecks.json.
- Dedicated jump, preview, timeout, and optional falling sounds are not supplied. Temporary substitutions are functional and listed above.
- Character animation is intentionally procedural, not a production motion-capture rig. The supplied walking/running FBX clips remain unused.
- The Web renderer intentionally omits realtime shadow maps and expensive effects for compatibility and mobile cost.
- PlayerPrefs is local browser persistence, not a secure or cloud wallet. Device vibration is optional and unverified on hardware.
- No public deployment or physical-device launch is claimed. No current source-compilation or Web-build blocker remains.

Rules and balance
- Three-second countdown; 20-second authoritative active gameplay clock.
- Default spawn interval 0.45-0.75 seconds; exposed life 1.4-2.1 seconds;
  rise/retreat 0.15 seconds; maximum five active and two bombs.
- Start with two coins; bombs available after one second, nominal 18% selection.
- Coin values 10/20/50/100 weighted 45/30/18/7. Force a coin opportunity when
  all exposed targets are bombs. Never replace occupied targets.
- Unlimited shots and retries; misses have no penalty. Bomb removes current
  round earnings only. Success automatically banks all pending earnings.
- No entry costs, wagers, shops, upgrades, ads, combos, or multiplayer.

Architecture and assets
- Assets/Bullseye/Scenes/BullseyeBlitz.unity is the playable build scene.
- Assets/Bullseye/BlitzConfig.asset stores timing, rewards, weights, and artwork.
- RoundRules owns states/clock/pending earnings. BlitzGame coordinates terminal
  transitions and screens. BoothSpawner owns scheduling and active limits.
- BoothTarget owns a slot's lifecycle and activation ID; nine instances are
  reused. Consume disables its collider and validates exposure at shot time.
- BlitzPointer polls only the new Input System and processes input in LateUpdate.
  UI blocking uses a fresh EventSystem raycast at the actual pointer position.
- BlitzUI builds Canvas controls and safe-area menus. BlitzAudio owns two audio
  sources. BlitzFeedback preallocates twenty cosmetic feedback objects.
- WalletStore owns versioned save data. BlitzBrowser supplies browser storage,
  optional vibration, and read-only QA telemetry when the URL contains ?qa=1.
- Prefabs: BoothTarget and BoothDecoration, under Assets/Bullseye/Prefabs.
- Initial setup refuses to overwrite an existing playable scene. Normal builds
  do not regenerate scene/configuration/assets.

Rendering and hit detection
- Orthographic camera, unlit URP sprites, no 3D target physics.
- Sorting layers: Backdrop, Targets, ShelfFronts, Effects, UI.
- Reveal masks are restricted to each row's target sorting-order range.
- Target labels render only while exposed; shelves cover retreating artwork.
- Target layer 8; intentional shelf blocker layer 9. Physics2D.OverlapPointAll
  queries only these layers. Frontmost eligible target uses explicit order;
  overlap query enumeration order is never treated as rendering order.
- Pointer conversion uses the gameplay camera and z=0 plane depth.
- Camera size and slot spacing adapt independently of Canvas UI. Resizing does
  not reset round state, target identity, type, value, or activation ID.
- Crosshair and labels do not intercept Canvas raycasts.

Timing, pause, wallet
- RoundRules is the sole active gameplay clock. Spawn/target timing consumes it.
- Every shot synchronizes the clock before resolving. At time >=20 success wins
  and input is rejected. Earlier bomb hits immediately transition to failure.
- Pause freezes clock/targets/spawning and uses a fully opaque overlay. Browser
  focus/visibility loss requests pause; Resume consumes the interaction.
- Restart/Home confirmation states the number of pending coins to discard.
- Save format v1 contains integer wallet/best/completed counts, settlement ID,
  music/sound volumes, reduced effects, and optional vibration.
- Browser saves use one localStorage record and verify the written string before
  completed payout is shown. Editor uses PlayerPrefs. Local saves are editable,
  origin-specific, and have no backend security or tamper-proof guarantee.
- A failed settlement rolls back the in-memory wallet and exposes Retry saving.
  Pending earnings are never saved as a completed round. Missing/corrupt data
  falls back safely to defaults. Save operations occur during settlement/settings,
  not only on unload or application quit.

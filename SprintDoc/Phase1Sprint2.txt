3. CORE RULES PRESERVED AND STRENGTHENED
---------------------------------------
- Exactly 25 cells, arranged in five rows and five columns.
- Mine selection from 1 to 24; initial default remains 3.
- Unique mine placement using a partial shuffle and injectable System.Random.
- Mine positions fixed for the entire round.
- First reveal can hit a mine.
- Mine selector locked during play.
- Repeated tile reveals and ended-round inputs rejected.
- Finish Game available throughout active play.
- Finish before revealing awards zero.
- Full safe-board completion banks automatically.
- Mine hit forfeits unbanked reward.
- Play Again resets the board and round.

Round now exposes a unique round ID and the triggered mine index. A separate
Forfeit operation ends an active round without banking its potential reward.
UI completion is guarded against repeated presentation, and wallet banking
rejects a duplicate completion ID. Rewards are committed before effects run.

4. ECONOMY CORRECTION
---------------------
Sprint 1 converted points into coins using a divisor of 10. This sprint follows
the supplied prompt's direct-coin example instead:

Reward per safe tile = pointsPerGem x selected mine count.
Default pointsPerGem = 10.
Banked wallet coins = current accumulated gameplay reward.
Lifetime gameplay points increase by the same banked amount.

Example:
3 mines x 10 base reward = 30 coins for each safe reveal.
4 safe reveals = 120 bankable coins.
Finishing adds 120 wallet coins and 120 lifetime gameplay points.
A mine awards zero coins for that round.

There is no entry fee, hidden full-board bonus, or cash value.
Removed the pointsPerCoin conversion field from the configuration source.
Updated How to Play and README to explain the actual formula.

7. DAILY WHEEL AND INTERRUPTION RECOVERY
---------------------------------------
Configured six equal-probability coin rewards:
50, 75, 100, 150, 200, 300.

Spin sequence:
1. Check UTC cooldown and reject an existing pending reward.
2. Choose a reward segment.
3. Save pending coin amount and next eligible UTC timestamp.
4. Animate the six-segment wheel beneath the fixed pointer.
5. Present CLAIM REWARD.
6. On claim, credit coins and clear pending state in the same saved snapshot.

Wallet credit no longer happens before the animation as it did in Sprint 1.
Restarting with pending coins presents the claim flow again. Repeating claim
cannot award again because pending state is cleared after the first claim.
Cooldown remains 24 hours from spin start. A saved reward amount is independent
of later animation timing or wheel rotation.

A clock function can be injected into SaveService for deterministic tests.
The countdown is computed from UTC each time and survives restarts.
This is a local prototype: device-clock changes and editing local save data
are not prevented. Local PlayerPrefs is not a transactional backend.

---------------------------------

Saved data:
- Explicit version number.
- Wallet coins.
- Lifetime banked gameplay points.
- Completed round count.
- Last banked completion ID.
- Last-selected mine count.
- Sound mute and reduced-effects settings.
- Next daily UTC timestamp.
- Pending daily reward coin amount.
- Claimed milestone indices.

If v2 is absent and v1 exists, retain old wallet/progression/round count/mute/
cooldown values. Initialize mine selection to 3. Reset milestone claim flags
for the new ladder because its thresholds differ; old awarded coins are kept.
No historical balances are multiplied to match the new economy.

Malformed or missing JSON falls back to defaults. Negative wallet/progression/
round counts are clamped, mine selection is clamped to 1-24, and claim lists
are initialized/deduplicated. Wallet additions use a long intermediate and
saturate at int.MaxValue to avoid addition overflow.

Active rounds remain unsaved by design. This implementation does not promise
power-failure guarantees, anti-cheat, or cloud sync.

GAME CONCEPT
MineGrid is a casual risk-and-reward tile game:
1. Choose the number of hidden mines.
2. Start a round.
3. Reveal tiles to find gems and grow the potential reward.
4. Press Finish Game to bank the reward before hitting a mine.

Use virtual coins and points.

Treat the attached screenshots as visual references for colorful casual-game presentation, chunky buttons, reward panels, and polished transitions. The Mines rules below define the gameplay.

Do not introduce unrelated merge mechanics, tool inventories, or mining-drop gameplay from the screenshots.

CORE RULES
- The board is exactly 5 columns by 5 rows: 25 tiles.
- The player selects between 1 and 24 mines before starting.
- Default to 3 mines.
- Provide a slider or stepper with an exact numeric value and optional quick presets.
- Show the number of mines and total safe tiles.
- Start Game creates the round and assigns the selected number of mines to unique randomly selected cells.
- Generate mine positions once per round and keep them fixed.
- Do not guarantee that the first reveal is safe.
- Disable mine selection during an active round.
- A tile can be revealed only once.
- A safe tile reveals a gem, increments the safe-reveal count, and updates the potential reward.
- A mine ends the round immediately and forfeits the unbanked reward.
- After a loss, reveal remaining mines and distinguish the triggered mine.
- Finish Game remains available throughout an active round.
- Finishing banks the current reward exactly once and ends the round.
- Finishing before revealing any safe tile awards zero coins.
- Revealing all safe tiles automatically wins and banks the reward exactly once.
- Play Again returns to setup with the previous mine count selected and a fresh hidden board.
- Block tile input during setup, after the round ends, and while blocking popups are open.
- Handle rapid input without duplicate reveals or duplicate rewards.

SCORING AND ECONOMY
Use a transparent arcade scoring system:
- No entry fee.
- Default reward per safe reveal = 10 × selected mine count.
- Current bankable reward = safe tiles revealed × reward per safe reveal.
- Example: with 3 mines, each safe tile adds 30 coins; revealing 4 safe tiles makes 120 coins available to bank.
- A loss awards zero coins for that round.
- A full-board victory banks the same accumulated reward, without a hidden bonus.
- Make the base reward configurable in a central configuration asset.
- Show the current bankable reward and the next safe-tile reward.
- Clearly explain these rules in How to Play.
- Persist banked coins and lifetime banked gameplay points.
- Keep daily rewards and milestone coin rewards separate from lifetime gameplay points to avoid progression loops.
